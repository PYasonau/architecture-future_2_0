## Проблемные места

### 1. Перегруженная и монолитная структура DWH

Текущая архитектура DWH основана на устаревшей версии SQL-сервера 2008 года с интегрированной бизнес-логикой. Это приводит к снижению производительности при выполнении сложных аналитических запросов и построении отчётов, особенно при увеличении объёмов данных и усложнении вычислений. Внедрение отдельных доменов и сервисов позволило бы уменьшить зависимость от DWH и повысить гибкость управления данными.

### 2. Смешение данных из разных доменов

В DWH одновременно находятся медицинские, финансовые и операционные данные. Это создаёт риски несоответствия требованиям по защите данных и усложняет управление доступами. Сегментация данных по доменам позволит установить более чёткие правила безопасности и управления данными, а также снизит риски потенциальных утечек данных.

### 3. Сложности с поддержкой устаревших интерфейсов

Power Builder — это устаревший инструмент, который сложно интегрировать с современными технологиями и системами. Это снижает скорость обновления функциональности и адаптации системы под новые бизнес-требования. Переход на современные интерфейсы и API-ориентированную архитектуру упростит взаимодействие с другими системами и повысит гибкость.

### 4. Отсутствие чётких стандартов и политики работы с данными

В текущей системе отсутствуют формализованные стандарты обработки данных и их актуализации. Это затрудняет управление данными и может приводить к несоответствию аналитики текущим бизнес-целям. Внедрение унифицированных стандартов обработки данных, а также создание каталогов данных и правил их актуализации станет основой для повышения качества аналитики.

### 5. Устаревший стек технологий и инфраструктуры

Сервер SQL 2008 больше не поддерживается и представляет собой потенциальную уязвимость в контексте безопасности и производительности. Обновление до PostgreSQL или аналогичных современных решений позволит устранить узкие места, повысить масштабируемость и упростить поддержку системы. Кроме того, обновление шины Apache Camel и переход на более современные платформы интеграции позволит улучшить взаимодействие между системами.

## Приоритизация по WSJF

**1. Высокий приоритет:**

* Обеспечение соответствия требованиям законодательства по персональным данным
* Внедрение событийной шины для интеграции новых сервисов
* Ускорение построения отчетов через кэширование
* Повышение отказоустойчивости системы
* Обновление SQL Server до PostgreSQL
* Внедрение потоковой обработки данных (streaming ETL)

**2. Средний приоритет:**

* Сегментация данных по доменам
* Внедрение мониторинга нагрузки системы
* Создание системы тегирования данных и разграничения прав доступа с помощью ABAC
* Обновление PowerBuilder и Apache Camel

**3. Низкий приоритет:**

* Расширение BI-портала с функциями ML-аналитики
* Создание витрин данных для различных доменов

**4. Не приоритетные задачи:**

* Полный отказ от SQL-сервера (переход будет поэтапным)
* Кастомизация ИИ-моделей под все бизнес-направления
* Обновление документации (низкий приоритет)
* Полный отказ от всех устаревших систем (будет происходить постепенно)

## Рекомендации и доработки

1. Внедрить переход на PostgreSQL или аналогичное решение, чтобы снизить риски, связанные с устаревшим SQL Server 2008.

2. Добавить функциональность мониторинга нагрузки и кэширования данных для обеспечения высокой производительности при аналитических запросах.

3. Внедрить ML-аналитику для ключевых доменов, таких как `production-domain` и `fintech-domain`, чтобы обеспечить продвинутую аналитику и прогнозирование на основе данных.

4. Обновить `Apache Camel` до более современной версии или рассмотреть альтернативные интеграционные платформы для улучшения производительности и совместимости.

5. Проработать схему построения `витрины данных`, включив возможности динамической генерации отчётов для пользователей различных доменов.
